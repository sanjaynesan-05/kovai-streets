# Kovai Streets 2.0: Phase 0 Technical Audit

This audit follows the brief in `TODO.TXT` (sections 1, 22 and 24). **No game code was changed in Phase 0.** Everything below comes from reading the source and running the game in Chrome.

- **Audited version:** commit `625607f` (2026-11-19)
- **Audit date:** 2026-11-22

---

## 1. Summary

- **The whole game is one 292 KB file**, `index.html` (2,426 lines, about 307 functions in a single closure). It runs on Three.js r128. All models, textures and sounds are generated by code at load time. There are no asset files.
- **Both critical bugs are confirmed and their root causes found:**
  - **Flyover:** a single collider line fills the space under the deck with a solid block.
  - **Passenger:** the passenger code hides anyone riding with you, whatever the vehicle. Two-wheelers have no pillion seat.
  - Both are small, safe fixes (section 5).
- **Some brief items already exist.** These include a save system, the story, collectibles and police tiers. Many others need new systems: the economy, heists, voice acting, gang territory AI, district population, traffic signals and interiors. Some need decisions or assets only you can provide, mainly voice audio and real faces (section 8).
- **Biggest structural risk:** every phase adds to one large file, and the save format has no versioning or migration. I recommend two groundwork steps before Phase 1 (section 9):
  1. Save-schema versioning with a backup copy of the save.
  2. A mechanical split of `index.html` into classic script files, with no change in behaviour.

## 3. Architecture (as actually implemented)

Line numbers refer to `index.html` at commit `625607f`.

| System | How it works | Key places |
|---|---|---|
| **Entry and boot** | `<script src="three.min.js">`, then one inline IIFE. `init()` runs 30 ms after load. The main loop is `requestAnimationFrame(loop)` → `update(dt)` (dt capped at 0.05 s) → `renderer.render`. An attract-mode camera orbits before Play | `init` ~2398, `loop`/`update` ~2380 |
| **Rendering** | One `WebGLRenderer`, Lambert/Phong materials, PCF soft shadows (quality-dependent). Static world geometry is **merged into a few large batched meshes** (`B_WIN`, `B_FAC[]`, `B_SHOP`, `B_ROAD`, `B_SIDE`, `B_CURB`, `B_PLAIN`, `B_FAR`). Palms, trees and lamps use `InstancedMesh`. Custom GLSL for the sky dome and water | batching ~332, `finish()` |
| **Quality** | `QL` from URL hash or localStorage `kovaiQ`. `QS` sets pixel ratio, shadow map size, number of people, traffic target and tree count | ~276 |
| **Collision** | **Axis-aligned boxes** `{minX,minZ,maxX,maxZ,h,y0}` in a 16 m spatial-hash grid. `pushCircle()` resolves circles against boxes, height-aware (it skips a box if the actor is above its top or below its bottom). `rayBoxes()` (line 324) **loops over every box** for bullets and line of sight. Walkable raised surfaces (flyover, mall floors, jetty, ramps) are a separate `SURF[]` list of height functions, used by `surfaceH()` | 307–331 |
| **Characters** | `makeHuman()` (line 1480) merges torso, head, face and hair into **one vertex-coloured mesh**, plus separate jointed leg, shin and arm meshes. No skeleton, no UVs and no textures. Procedural animation (`animHuman`, `seatPose`, `pedalPose`, `punchAnim`) | 1480–1522 |
| **Vehicles** | 25 types in `VT` (mass, speed, grip, collision circles). Meshes from extruded side profiles (`makeVehicleMesh`). Physics in `driveUpdate`/`integrate`/`vertical`: arcade model with lateral grip, slopes and buoyancy for boats. Vehicle-to-vehicle collisions use circle impulses, O(n²) in `collideVehicles` (line 876) | 501–566, 832–926, 1523–1648 |
| **Traffic AI** | Waypoints on the 11 × 11 road grid (`laneWP`, `aiNext`), keeping left. `blockedAhead` gives car following. **No traffic signals or junction logic.** Cars only drive inside the city grid. Target count is 30–52 by quality, with a cap of 80 vehicles | 540–566 |
| **Pedestrians** | `peds[]` walk loops around each block's pavement (`pedPos`). Same density in every block. Flee, talk and fight states. Separate "wanderers" for the market, beach, college and stadium | 592–654, 1788 |
| **Gangs** | `goons[]`, 7 fixed hangouts of 4. **Any goon within 36 m becomes hostile and starts shooting** (line 646). Hangouts respawn after 100 s. Cops on foot reuse the goon system with `cop:true` | 638–654 |
| **Police / wanted** | Stars 0–5. `addWanted()` is called directly by events (killing a pedestrian, destroying a police car…) with **no witness check**. Police cars chase. Version 2 added foot officers, roadblocks (3+ stars) and a helicopter (4+ stars) | 927–952, 2192–2257 |
| **Missions** | One `mission` object at a time. Jobs via `startMission()` (line 1069). Story and rampages use a newer **stage framework** (`stGo`, `stKill`, `stBoss`, `stWreck`, `stSay`, run by `stageTick`). The HUD panel reads `mission.title`/`txt`/`timer` | 1043–1104, 2093–2141 |
| **Economy** | `player.cash`. Money comes from jobs, the story, pickups and collectibles. It's spent at the gun shop (10 items), tea stalls, friend gifts, coffee and the ₹5,000 safehouse. **No clothing shops, dealerships, upgrades, businesses or other properties** | 953–971, 2059–2092 |
| **Friends** | `FRIENDS[]` (Meena, Divya): friendship 0–100, hang-outs, gifts, companion combat, perks | 972–1042 |
| **Save** | localStorage `kovaiSave1`, JSON `{v:1,…}`, written every 30 s, on events, on pause and on `beforeunload`. Settings are stored separately in `kovaiSettings1` | 2042–2058 |
| **UI** | Plain HTML/CSS overlays in `index.html`: HUD, minimap (2D canvas), big map, weapon wheel, talk/shop panels, pause, settings and touch controls | HTML top of file, HUD ~1192 |
| **Audio** | All Web Audio synthesis: master gain `OUT`, `RADIO_G`, engine oscillator with LFO, siren, filtered noise for effects and rain, procedural radio and ambience. **No audio files.** Only master and radio volume controls | 1267–1288, 2269–2314 |
| **Input** | Keyboard/mouse with pointer lock. Touch: joystick, swipe look and on-screen buttons | 1289–1373 |
| **Debug hook** | `window.__game` exposes state, and `__game.step(dt,n)` runs the update loop (used for automated testing) | end of file |

### How the map is built

- **Roads:** flat textured quads on a 74 m grid (`CELL`), 11 × 11 roads. The main roads (z = 0 and x = 0) run out to ±560.
- **Blocks:** each block has a `BUILD[type]` function (city, lake, park, temple, mall, market, mill…). Buildings are textured boxes with box colliders.
- **Flyover (`buildFlyover`, line 1818):** visual deck, ramp and parapet boxes. The walkable deck is a `SURF` height function, plus colliders for parapets and pillars, and the faulty under-deck block (section 5.1).
- **Western Ghats:** a 6 m heightfield (`rawMountain` noise) with a Catmull-Rom ghat road carved into it (`buildTerrainGrid`/`buildTerrainMesh`). The mesh is vertex-coloured with a detail texture.
- **Ghats vegetation (`buildTrees`, line 1702):** one trunk, two cone-layer `InstancedMesh`es, all the same shape. Placement is a hash test **on each 6 m grid cell** (line 1678), so trees follow the grid. **There are no grass, shrub or rock meshes.**
- **Coast:** a separate heightfield, a wave-shader sea and its CPU twin `waveY()` for buoyancy.
- **Gated areas:** invisible full-width walls at x = −552 (Ghats) and x = 578 (coast), switched off by Respect level or story progress.

## 5. Critical bugs: root causes (TODO §2)

### 5.1 Flyover: you can't pass underneath (confirmed)

**Reproduced:**
- Walking north along the cross street at x = 150 stops at **z = −6.9**.
- A car stops at **z = −8.8**.
- The deck spans z = −6.5 to +6.5, so the space underneath is blocked.

**Root cause:** `index.html` line 1827, inside `buildFlyover()`:

```js
if(lo>2.2)addCollider(x,-hw,x+8,hw,lo-0.45,-1)
```

- **What it does:** for every 8 m slice where the deck is more than 2.2 m up, it adds a box **from y = −1 up to just below the deck, across the full 13 m width**. That's a solid wall filling the whole space under the main span (about x = 99–327).
- **Probable intent:** stop things wedging under the low end of the ramps. It's applied far beyond that.

**Effects:**
- The three cross streets under the flyover (x = 148, 222, 296) are blocked for the player, traffic AI (they get stuck and respawn), police and pedestrians.
- Bullets and line of sight are blocked too, and the third-person camera collides with it.
- **Film reel #20 ("under the flyover", at 204, 0, 3) sits inside the block and can't be collected.** 100% completion is currently impossible.

**What is already correct:**
- The deck surface (`SURF`), parapets and pillars have their own colliders, so the deck stays solid from above.
- `pushCircle` is already height-aware, so no physics changes are needed.

**Proposed fix (small):**
- Replace that line with an under-ramp blocker only where the clearance is too low (deck underside below about 3.6 m, which is above the tallest vehicle). Use a top just below the underside.
- Optionally add a thin "deck slab" collider (`y0 = lo − 0.7`, `h = lo`) so nothing can come up through the deck.
- **Test:** walk, car, bike and bus under the deck at all three cross streets, from both directions. Check that the deck, parapets, pillars and ramps still work, that traffic doesn't stall, and that reel #20 can be collected.

### 5.2 Two-wheeler passengers disappear (confirmed)

**Reproduced:** with Meena following you, getting on a scooter gives `inCar: true, visible: false`. After you get off: `inCar: false, visible: true`.

**Root cause:** passengers are modelled as "in the vehicle = hidden", whatever the vehicle type. There is no seat or attachment.

- **Friends:** `updateFriends()` (line 1022, branch at line 1025) sets `f.inCar=true; h.g.visible=false` once you're within 8 m of a vehicle, then copies the vehicle position each frame. On exit, `inCar=false` and `visible=true`. This matches the report exactly.
- **Fare passengers:** `startMission` hides the passer-by (`p.hidden=true; p.h.g.visible=false`) for the whole ride.
- **Emergency-run patient:** has no character model at all.
- **No seat capacity:** both friends can "board" a one-seat bicycle at once.
- **The player rider is already handled:** the per-frame block in `update()` sets the player's position, lean and `seatPose`/`pedalPose`. The same approach can be reused for a pillion.

**Proposed fix:**
1. Add a seat model to each vehicle type in `VT`: pillion offset and seat count (0 for bicycle and sports bike, or allow a carrier seat on the bicycle; 1 for other two-wheelers; 1–3 for cars, autos and buses).
2. For two-wheelers and autos, **keep the passenger visible**. Each frame (after `integrate`), place them at the pillion offset in vehicle space. Apply the vehicle's heading, lean and pitch, use `seatPose` with hands holding the rider's waist, and push them slightly back to avoid clipping.
3. Inside closed cars, hiding is acceptable for now. Optionally show them seated behind the windows later.
4. Use one shared `boardPassenger`/`alightPassenger` path for friends and fare passengers, so they're restored correctly on exit and can't be lost if the camera changes or the vehicle is destroyed.
5. **Test:** every two-wheeler type (bike, cruiser, sports, scooter, retro, moped, bicycle) through acceleration, braking, lean, a crash ejection, wrecking, and exiting.

## 8. Technical constraints and decisions needed from you

1. **Opening the game by double-clicking `index.html` (`file://`) limits the options.**
   - Classic `<script src>` files work, so the code can be split across several `.js` files.
   - **ES modules (`type="module"`), `fetch()` and loading GLTF/JSON assets do *not* work from `file://`.** If you want real 3D models, voice files loaded by fetch, or modules, the game must be served (local server or hosted).
   - `<audio>` elements *do* play local files from `file://`, so pre-recorded voice lines can work without a server.
   - **Decision:** keep double-click support, or require a local server or hosting?
2. **Voice acting (§8):** I can build the dialogue audio system (line IDs, subtitles, volume, no overlap, fallback to browser speech synthesis). I can't produce authentic Tamil voice recordings in this environment. The audio files must come from you: recorded voice actors or a text-to-speech service you choose and configure. Browser Tamil voices vary by device and are often missing.
3. **Custom faces from photos (§4):** this needs the character rebuild from finding 7. Faces of identifiable real people need their permission, as the brief itself says.
4. **Scope:** heists, the economy, two character storylines, interiors and an expanded campaign are each a substantial system. I recommend delivering and testing them one phase at a time, as the brief requires, not in one release.
5. **Code structure:** I recommend splitting `index.html` into classic script files, as a mechanical move with no behaviour changes (section 9, step 0b). The brief says "avoid rewriting the entire game", and this is a move, not a rewrite. I'll only do it if you agree.
